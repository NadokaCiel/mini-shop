# 订单模块配套文档（MVP优先）

## 1. 模块目标

- 支撑完整交易闭环的“结果承接层”。
- 让用户快速了解订单状态并完成后续操作（支付、取餐、复购）。
- 降低订单咨询与售后沟通成本。

## 2. 业务范围（初期）

- 订单列表（按状态分组）。
- 订单详情（商品、金额、时间轴、取餐信息）。
- 关键操作：去支付、再来一单、取消订单、联系客服。
- 支付结果页基础承接（成功/失败）。

## 3. 页面与组件清单

### 3.1 订单列表页

- 状态Tab：全部、待支付、制作中、待取餐、已完成、已取消。
- 订单卡片：
  - 门店名称、下单时间、订单号
  - 商品摘要（前2-3项）
  - 订单金额、状态
  - 操作按钮（去支付/再来一单/查看详情）

### 3.2 订单详情页

- 状态头部：大状态文案（例如“制作中”）。
- 时间轴：下单 -> 支付 -> 制作 -> 完成。
- 取餐区：取餐码/核销码（自提）或配送信息（外送）。
- 明细区：商品列表、优惠、配送费、实付金额。
- 服务区：联系客服、申请售后（可先预留）。

### 3.3 支付结果页（轻量）

- 成功态：引导查看订单详情。
  - 失败态：可重试支付或返回订单列表。

## 4. 核心流程（主链路）

## 4.1 下单后查看订单

1. 用户支付完成后进入订单详情。
2. 可查看订单状态与取餐信息。
3. 完成后支持“再来一单”回流菜单。

## 4.2 待支付处理

1. 用户进入订单列表“待支付”。
2. 点击“去支付”进入收银台（或支付页）。
3. 支付成功后状态更新为“制作中”。

## 4.3 再来一单

1. 在完成订单卡片点击“再来一单”。
2. 系统尝试按原sku回填购物车。
3. 若部分商品下架/失效，提示并过滤后继续。

## 5. 状态机建议（简化）

- `pendingPay`（待支付）
- `paid`（已支付）
- `making`（制作中）
- `ready`（待取餐）
- `done`（已完成）
- `cancelled`（已取消）
- `refundProcessing`（退款处理中，可后续）

状态流转示例：

- `pendingPay -> paid -> making -> ready -> done`
- `pendingPay -> cancelled`
- `paid -> refundProcessing -> cancelled`（售后场景扩展）

## 6. 异常与边界处理

- **支付超时**：待支付订单自动过期并标记取消。
- **状态延迟**：列表与详情支持手动刷新+轮询兜底。
- **门店异常**：展示“门店繁忙”提示并引导联系客服。
- **商品变更**：历史订单展示以快照为准，不受当前商品变动影响。

## 7. 数据结构建议（前端）

- OrderSummary
  - `orderId` `orderSn` `status` `storeName` `createdAt`
  - `itemPreview[]` `payableAmount`
- OrderDetail
  - `orderId` `status` `timeline[]`
  - `items[]` `amountDetail`
  - `pickupCode` / `deliveryInfo`
- OrderAction
  - `canPay` `canCancel` `canReorder` `canRefund`

## 8. API协作建议（结合当前项目）

- 模块建议新增：`src/api/modules/order`
- 关键接口（MVP）：
  - `queryOrderList`
  - `queryOrderDetail`
  - `cancelOrder`
  - `reorder`
  - `queryPayStatus`
- 调用规范沿用当前工程：
  - `const [result, typeDeclaration] = await getOrderHttp().queryOrderList(...)`
  - 统一使用 `result.isOk / result.getMsg() / result.getData()`

## 9. 交互与视觉要点（订单模块）

- 状态信息优先级最高，颜色与图标必须直观。
- 操作按钮按主次分层（主按钮：去支付；次按钮：查看详情）。
- 列表卡片结构统一，降低扫描成本。
- 订单详情金额区保持高对比，避免误读。

## 10. 验收清单（MVP）

- 订单列表支持按状态筛选与分页加载。
- 订单详情信息完整且与列表一致。
- 去支付、再来一单链路可执行。
- 订单状态刷新及时，异常有明确提示。
- 历史订单可稳定查看，不受商品实时变更影响。
