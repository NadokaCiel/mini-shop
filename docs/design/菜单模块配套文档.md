# 菜单模块配套文档（MVP优先）

## 1. 模块目标

- 快速完成「选品 -> 选规格 -> 加购」核心链路。
- 降低用户决策成本，提高加购率与结算转化率。
- 支持后续活动扩展（联名、新品、限时口味）。

## 2. 业务范围（初期）

- 分类导航与商品列表展示。
- 商品规格选择（温度、甜度、杯型、加料）。
- 加入购物车、数量增减、删除。
- 活动标签与基础营销信息展示（不做复杂叠券）。

## 3. 页面与组件清单

### 3.1 菜单主页面

- 顶部区：门店信息、搜索入口、筛选入口（可先弱化）。
- 左侧区：分类导航（热销、新品、咖啡、非咖、甜品、周边）。
- 右侧区：商品列表卡片。

### 3.2 商品卡片（列表态）

- 商品图、名称、副标题。
- 价格区（原价/活动价预留）。
- 标签（新品、推荐、联名、限时）。
- 操作按钮（`+` 直接加购 / 点卡片进详情）。

### 3.3 商品规格弹层（核心）

- 基础信息：图、名、简介、当前价格。
- 规格组：
  - 温度：热 / 冰（部分商品固定）
  - 糖度：无糖/三分/半糖/全糖
  - 杯型：中杯/大杯（可影响价格）
  - 加料：奶盖/燕麦奶/浓缩加份（可影响价格）
- 数量器与确认按钮（加入购物车）。

### 3.4 购物车浮层/底部条

- 已选商品数量与合计金额。
- 进入购物车页入口。
- 起送/自提提示文案（根据模式显示）。

## 4. 关键流程（主链路）

## 4.1 标准下单前流程

1. 用户进入菜单页。
2. 选择分类并浏览商品。
3. 点击商品进入规格弹层。
4. 完成必选项后加入购物车。
5. 继续加购或跳转购物车/结算。

## 4.2 快捷加购流程

1. 在商品卡点击 `+`。
2. 若商品有默认规格，直接加购。
3. 若缺少必选规格，自动弹出规格层。

## 5. 状态与异常处理

- **空状态**：分类无商品时显示“该分类正在补货”。
- **加载状态**：骨架屏（分类和列表分区骨架）。
- **失败状态**：列表加载失败可重试，保留上次成功数据。
- **库存不足**：加购时提示“库存不足”，并刷新当前商品库存。
- **商品下架**：购物车中标记失效并阻断结算。

## 6. 数据结构建议（前端）

- Category
  - `id` `name` `sort` `icon`
- Product
  - `id` `title` `subTitle` `price` `coverUrl`
  - `tags[]` `stockCount` `status`
- SkuOption
  - `groupName` `required` `options[]`
- CartItem
  - `cartItemId` `productId` `skuSnapshot` `quantity` `amount`

## 7. API协作建议（结合当前项目）

- 模块建议归属：`src/api/modules/product`
- 关键接口（MVP）：
  - `getCategoryList`
  - `getProductList`
  - `getProductSkuDetail`
  - `addCartItem`
  - `updateCartItem`
  - `removeCartItem`
- 命名转换与返回规范沿用当前框架：
  - 响应自动 `snake_case -> camelCase`
  - 返回 `const [result, typeDeclaration] = await xxx()`

## 8. 交互与视觉要点（菜单模块）

- 操作反馈要“快”：加购按钮点击反馈 <= 120ms。
- 价格与CTA（加购）保持视觉聚焦。
- 规格弹层优先展示“已选结果”和“到手价”。
- 使用年轻化标签体系（新品、限定、社区热推）。

## 9. 验收清单（MVP）

- 可完整走通「选品 -> 选规格 -> 加购」。
- 缺失必选规格时可正确拦截。
- 加购数量与金额同步准确。
- 库存/下架异常有明确提示且不崩溃。
- 菜单页首屏渲染与滚动流畅。
